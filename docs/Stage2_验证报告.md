## 一、验证 1：pikepdf `page.rotate()` 实际旋转方向

### 1.1 测试样本

用 PyMuPDF 生成 **A4 横向方向标记样本**（297×210mm = 841.89×595.28pt）：
- 四角标注汉字「顶 / 右 / 底 / 左」（china-s 字体，30pt）；
- 页面中心画水平箭头 →（指向页面右侧）。

### 1.2 验证方法

1. pikepdf 打开样本，分别执行 `page.rotate(90)` 与 `page.rotate(270)`（`relative=True` 默认），另存 PDF；
2. PyMuPDF 打开输出，读取 `/Rotate` 值、显示尺寸，并用 `rotation_matrix` 将四角标记的未旋转坐标换算为**显示坐标**；
3. 依据「顶 / 底」显示坐标的 x 关系判定方向：
   - 原横向页「顶」在左上角（x 小）、「底」在右下角（x 大）；
   - 若旋转后「顶」x > 「底」x → 内容顺时针转（**顺时针 90°**）；
   - 若「顶」x < 「底」x → 内容逆时针转（**逆时针 90°**）。

### 1.3 实测数据

| 调用 | `/Rotate` | 显示尺寸(pt) | 「顶」显示坐标 | 「底」显示坐标 | 判定 |
|------|-----------|--------------|----------------|----------------|------|
| `page.rotate(90)` | 90 | 595.3 × 841.9（纵向） | (547.3, 75.0) 右上 | (52.0, 796.9) 左下 | **顺时针 90°** |
| `page.rotate(270)` | 270 | 595.3 × 841.9（纵向） | (48.0, 766.9) 左下 | (543.3, 45.0) 右上 | **逆时针 90°** |

### 1.4 结论（验证 1）

- **`page.rotate(90)` = 顺时针旋转 90°**；
- **`page.rotate(270)` = 逆时针旋转 90°**（即顺时针 270°）。

> 与技术方案 3.3.1 / 5.2 的假设一致（`90`=顺时针、`270`=逆时针），**无 API 行为不一致**。
> 因此：`detect_text_rotation()` 返回 90（顺时针）时调用 `page.rotate(90)`；返回 270（逆时针）时调用 `page.rotate(270)`。

## 二、验证 2：PyMuPDF 文字方向提取可靠性

### 2.1 测试样本

用 PyMuPDF 生成三个样本页（均为 A4 横向 841.89×595.28pt）：

| 样本 | 内容 | 生成方式 |
|------|------|----------|
| A | 文字水平排列（左→右） | `insert_text(...)`（默认方向） |
| B | 文字旋转 90° 排列 | `insert_text(..., rotate=90)` |
| C | 纯图片页（矩形 + 线条，无文字） | `draw_rect` / `draw_line` |

### 2.2 实测数据（`get_text("dict")` 的 line `dir` 字段）

| 样本 | blocks 数 | line `dir` 实测值 |
|------|-----------|-------------------|
| A（水平） | 3 | `(1.0, 0.0)`（沿页面宽方向，左→右） |
| B（旋转 90°） | 1 | `(0.0, -1.0)`（沿页面高方向） |
| C（纯图片） | 0 | 无文本 block（空列表） |

补充实测（不同旋转角对应 dir）：

| `insert_text` rotate 参数 | dir 实测 |
|---------------------------|----------|
| 0 | `(1.0, 0.0)` |
| 90 | `(0.0, -1.0)` |
| 180 | `(-1.0, 0.0)` |
| 270 | `(0.0, 1.0)` |

### 2.3 结论（验证 2）

- **`dir` 字段能可靠区分"水平排列"与"旋转 90° 排列"**：水平 = `(±1, 0)`，旋转 90° = `(0, ±1)`；
- **无文字页返回空 blocks**（`get_text("dict")["blocks"]` 为空列表），可作为"无文字回退"的判据；
- 说明：`get_text("dict")` 返回的是**内容坐标系**（未计入源页自带 `/Rotate`）中的 dir；源页 `/Rotate` 的存在不影响 dir 值（实测：纵向 MediaBox + `/Rotate=90` 的水平正文 dir 仍为 `(1.0, 0.0)`）。这一点在检测逻辑中需注意（结合"源页 /Rotate 叠加"D7 一起处理）。

## 三、补充验证：dir → 旋转角映射（"逆时针转书 90° 可读"标准）

### 3.1 背景

技术方案 3.3.2 假设："正文基线横向正读 → 90°；正文基线处于其他方向（如源页已带旋转）→ 270°"。本验证对该假设做端到端实测。

### 3.2 验证方法（端到端可读性）

对以下场景，分别用 pikepdf 施加 `rotate(90)` / `rotate(270)`，PyMuPDF 渲染，再用 PIL 模拟"读者将书逆时针旋转 90°"（`Image.rotate(90, expand=True)`），目检/OCR 判定转书后正文是否正读：

| 场景 | 内容形态 | 实测 dir |
|------|----------|----------|
| A | 横向页 + 水平正文 | `(1,0)` |
| B | 横向页 + 字符旋转 90° 正文 | `(0,-1)` |
| C | 纵向 MediaBox + 水平正文 + 源页 `/Rotate=90`（显示横向） | `(1,0)` |
| D | 横向页 + 字符正立的竖排正文（逐字插入） | 逐字均为 `(1,0)`（无法区分） |
| E180 | 横向页 + 水平 180° 正文 | `(-1,0)` |
| E270 | 横向页 + 垂直向上正文 | `(0,1)` |

### 3.3 实测结果

| 场景 | rotate(90) 转书后 | rotate(270) 转书后 | 正确角 |
|------|-------------------|--------------------|--------|
| A（水平正文） | 正读 ✓ | 水平倒读 ✗ | **90** |
| B（字符旋转 90°） | 竖排正读 ✓ | 竖排乱码 ✗ | **90** |
| C（源页 /Rotate=90） | 正读 ✓ | 倒读 ✗ | **90** |
| D（字符正立竖排） | 顺序颠倒 ✗ | 字符倒立 ✗ | 均不可读（检测盲区） |
| E180（水平 180°） | 水平镜像 ✗ | 竖排顺序反 ✗ | 均不可读（极罕见） |
| E270（垂直向上） | 竖排正读 ✓ | 倒读 ✗ | **90** |

### 3.4 结论与处理

1. **绝大多数真实"需旋转页"场景（A/B/C/E270），`rotate(90)`（顺时针）均使"逆时针转书 90° 后可读"成立**；
2. 技术方案 3.3.2 中"正文基线处于其他方向（如 dir=(0,-1)）→ 270°"的假设 **与实测不符**：字符旋转 90° 正文（dir=(0,-1)）实测 rotate(90) 转书后正读、rotate(270) 转书后乱码。**检测映射修正为：需旋转页有文字时默认返回 90（顺时针）**；
3. `detect_text_rotation()` 仍执行方向检测并输出 `detected_rotation`，但**默认值以实测为准取 90**；对极端/无法判定的情况（无文字、字符正立竖排、方向异常）**回退默认 90° 并在 UI 提示用户确认**；用户可通过 `rotation_override`（auto/cw90/ccw90/none）最终覆盖（技术方案 4.3 / UI 说明 4.3）。
4. 该修正属于 `detect_text_rotation` 的实现参数（Stage2 提示语 5.3.3 明确"根据前置验证 2 的结论实现"），不属于 API 行为与技术方案不一致，故不暂停；但已在本报告如实记录，供指导者审查知悉。

## 四、对 Stage 2 实现的影响

1. **`output.py` 旋转调用**：按 `final_rotation` 返回的角（90/270）直接调用 `pikepdf page.rotate(angle, relative=True)`，语义与技术方案一致（90=顺时针、270=逆时针）。
2. **`engine.detect_text_rotation(page_text_data)`**：
   - 输入为 `get_text("dict")` 返回的 dict；
   - 统计文本 line 的 dir（按文本量加权）；
   - 有文字 → 返回 90（实测正读）；特殊方向（`(-1,0)`）→ 返回 270 建议并提示；
   - 无文字 → 返回 90（回退默认）并提示用户确认；
   - 由 `final_rotation()` 结合 `rotation_override` 得到最终角。
3. **`plan_rotation()`**：判定表不变（A4 横向、A3 纵向需旋转），对需旋转页调用 `detect_text_rotation()` 填充 `detected_rotation`。
