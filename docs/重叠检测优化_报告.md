## 二、优化前 vs 优化后

| 维度 | 优化前 | 优化后 |
|---|---|---|
| 检测对象 | 仅 `get_text("dict")` 文本块（type=0） | 文本块（快且精确）+ 像素级补充 |
| 扫描件（整页图片） | 文本块为空 → 永远检测不到 | 像素检测命中 → 报重叠警告 |
| 命中收集 | 只记录第一个重叠块 | 收集所有重叠区域（`list[rect]`） |
| 旋转坐标 | `_text_block_calculator` 用 `pp.rotation`（仅规划旋转），源页带 `/Rotate` 且 `planned_rotation=0` 时坐标不回正 | 用总旋转 `source_rotation + planned_rotation`，与 `calculate_number_position` 一致 |
| 空白页码误报 | — | 像素检测默认阈值过滤噪点，空白页不误报 |

### 混合检测流程（每页有页码时）
```
1. 文本块检测（现有逻辑，收集所有命中）
2. 文本块未命中 → 像素检测（渲染页码区域小矩形，统计非白色像素）
3. 任一命中 → 报重叠警告（像素命中时 overlap_rect 用页码 bbox）
```

## 三、像素检测方案说明

**函数**：`engine.detect_pixel_overlap(page, number_rect_pt, dpi=150, brightness_threshold=230, min_overlap_pixels=30)`

**原理**：渲染页码区域小矩形（不整页渲染），逐像素统计亮度低于阈值的像素总数。

| 参数 | 值 | 说明 |
|---|---|---|
| dpi | 150 | 30×15pt 页码区 → 约 63×31 像素 |
| brightness_threshold | 230 | 纯白(255)不触发、浅灰背景(240+)不触发、文字/线条(<200)触发 |
| min_overlap_pixels | 30 | 非白色像素总数阈值，过滤零散噪点 |

**实现选择**：用"区域内非白色像素**总数** > 阈值"而非提示语建议的"连续像素"判定。理由：斜体/细线文字笔画断续，连续判定易漏报；总数统计更稳健、确定性更好。阈值 30（约 2000 像素的 1.5%）足以过滤单点/零星噪点。

**性能**：单页仅渲染 ~2000 像素区域 + 纯 Python 扫描，实测 < 1ms；800 页全量 ~800ms，可接受。

## 六、实现中发现的两个隐藏 Bug（本次顺带修复）

### 1. `_text_block_calculator` 依赖 `current_plan` 的时序缺陷
原实现从 `self.current_plan` 反查该页 rotation 做坐标变换。但 `build_process_plan` 构建**过程中** `current_plan` 尚未更新（首次 `open_pdf` 时为 None），导致带 `/Rotate` 页在首次构建时坐标不回正。修复：`build_process_plan` 算法 5 计算总旋转传入回调，`_text_block_calculator` 直接使用传入值。

### 2. fitz `page.rect` 对带 `/Rotate` 页返回显示尺寸
`get_text("dict")` 的 bbox 基于**未旋转坐标系**，而 `page.rect` 对 `/Rotate=90/270` 页返回**旋转后显示尺寸**。原代码用 `page.rect` 当内容尺寸做坐标变换 → 坐标错乱（block y 值超出页面高度）。修复：`/Rotate=90/270` 时交换宽高还原内容尺寸。
