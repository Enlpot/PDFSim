## 一、需求与目标

检测到页码重叠后，自动向页面边缘移动页码避开重叠；移动到边界仍重叠则缩小字号。全局设置开关（默认开）+ 缩小级别（默认 2 级，每级 1pt）。

**调整规则**：
1. 方向：向最近的角落移动（保持位置属性，只调偏移量）
2. 步长：0.5mm/次
3. 最小页边距：3mm（页码边缘距页面边缘 ≥ 3mm）
4. 只调重叠的那一页，不影响其他页
5. 移动到边界仍重叠 → 缩小字号（每级 1pt，最多 N 级，最小 6pt），缩小后位置不变
6. 都不行 → 保留原位置 + 重叠警告
7. 自动调整后同时显示"叠"+"自"两个角标

## 二、实现机制说明

### 与实际代码结构的适配

提示语中的设计基于"`position`/`vertical_offset_mm`/`horizontal_offset_mm`/CENTER 枚举"的假设结构，但**实际代码**的 `PageNumberStyle` 用 `margin_left/right/bottom/top_mm` + `vertical_position`（bottom/top），`PageNumberPos` 无 CENTER。故自动调整基于实际结构实现：

| 页码位置 | 移动方向 | 实现 |
|---|---|---|
| BOTTOM_RIGHT | 向右下角 | `margin_right` 减小 + `margin_bottom` 减小 |
| BOTTOM_LEFT | 向左下角 | `margin_left` 减小 + `margin_bottom` 减小 |
| TOP_RIGHT | 向右上角 | `margin_right` 减小 + `margin_top` 减小 |
| TOP_LEFT | 向左上角 | `margin_left` 减小 + `margin_top` 减小 |
| CUSTOM | 不自动调整 | 用户精确定位，尊重意图 |

### 流程（build_process_plan 算法 4.5）

```
算法 4（初算 number_point，用 style_override or global）
   ↓
算法 4.5（自动调整，仅 auto_adjust_overlap=True 时）
  1. 跳过：无页码 / 总旋转≠0（含源页自带 /Rotate）/ 空白页
  2. 用当前 style 检测是否重叠（文本块 + 像素混合，复用算法 5 检测逻辑）
  3. 无重叠 → 跳过
  4. 有重叠 → auto_adjust_overlap：
     阶段 1 向边缘移动（0.5mm/步，最小 3mm）→ 不重叠则成功
     阶段 2 缩小字号（每级 1pt，最多 config.auto_shrink_levels 级，最小 6pt）
     → 成功则写 effective_style + 重算 number_point；失败保留原位置
   ↓
算法 5（最终重叠检测，用 effective_style 计算页码矩形）
```

### 关键设计：per-page effective_style

- `ProcessedPage.effective_style`：该页实际生效样式（自动调整后的副本）；None=沿用全局/覆盖
- 算法 4/5 与 output 写页码统一用 `effective_style or style_override or global_style`
- 只写重叠那页的 effective_style，**不影响其他页**（不污染全局/单页覆盖配置）
- 自动调整失败时不写 effective_style → 输出保持原位置原字号

### 最小字号保护
缩小不超过 6pt；`auto_shrink_levels` 限制 0~4 级。

## 五、实现中发现的细节

### 旋转页判定须用"总旋转"而非 planned_rotation
初版算法 4.5 用 `pp.rotation != 0` 判断旋转页跳过。但**源页自带 `/Rotate=90` 且文字正向（planned=0）**时 `pp.rotation==0` → 误入自动调整，把带 /Rotate 页的页码也移动了（破坏原有"带 /Rotate 页保留重叠警告"的坐标回正行为）。修复：判定改为 `(source_rotation + rotation) % 360 != 0`（与 `calculate_number_position` 的总旋转一致）。

## 六、性能优化（CI 回归修复）

### 现象
`build_process_plan` 初版算法 4.5 引入后，GitHub Actions 的 `ci.yml` 全量测试在共享 runner 上**稳定失败**：

```
FAILED src/tests/test_performance_optimization.py::TestPerformance800::test_800pages_open_under_10s
E  AssertionError: 800 页打开 11.2s ≥ 10s     （assert 11.1576549 < 10）
```

本地（Python 3.13 / 3.12 + offscreen）全量均为 377 passed 全绿，无法本地复现，曾误判为 runner 波动，重跑仍失败后才定位。

### 根因
- 算法 4.5（自动调整）与算法 5（最终检测）**各自对每页跑一遍完整的重叠检测**（文本块 `detect_overlap` + 像素检测）。
- 800 页大文档下，每页检测两次 = 约 2 倍检测开销，叠加共享 runner 比本机慢 20~30%，把"800 页打开"从 <10s 推到 11.2s 触顶。
- 这既是 CI 失败原因，也是真实用户打开大文件时的性能回归隐患。

### 修复：单遍检测 + 结果缓存复用
重构 `build_process_plan` 的算法 4.5/5 为**单遍检测**：

```
第一遍（原算法 4.5 前）：遍历所有有页码页，统一检测一次（文本块 + 像素），
  结果 (text_hits, pixel_hit, num_rect) 存入 detect_cache[physical_index]
    ↓
算法 4.5（自动调整）：只处理 detect_cache 中判定为"重叠"的页；
  无重叠页完全跳过（不再重复检测）；调整成功后用新 effective_style 重新检测并更新缓存
    ↓
算法 5（警告）：直接读 detect_cache（未重叠页复用第一遍结果；调整页用更新后的结果）
```

新增辅助 `_detect_hits(pp, style, text_width_pt, text_block_calculator, pixel_overlap_checker)`，统一封装"文本块 + 像素混合检测"逻辑，供第一遍与调整后重检复用；原 `_rect_overlaps` 保留（供 `auto_adjust_overlap` 的 overlap_fn 回调使用）。

**关键收益**：未重叠页（大文档中绝大多数）只检测一次，800 页从 2 遍降到约 1 遍；仅重叠页（少数）因调整重检一次。

### 逻辑等价性
- 检测判定条件、警告生成逻辑、自动调整触发条件**完全不变**，只是把"同一页在 4.5 和 5 各算一次"合并为"算一次 + 缓存"。
- 全量 377 passed 通过（本地 3.13 + 3.12/offscreen 双验证）；推送到 CI 后 `ci.yml` **恢复 success**。
- 实测 800 页打开耗时回稳（CI 上回到 10s 内）。
