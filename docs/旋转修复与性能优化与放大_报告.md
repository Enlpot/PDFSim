## 一、任务 1：旋转方向修复（两步法 + 源页 /Rotate 坐标修正）

### Bug 背景

原 `detect_text_rotation` 只考虑"让文字 dir 变成 (1,0)"，不区分"页面是否必须旋转"，导致：

- A3 纵向 + 水平文字 → 返回 0 → 不旋转 → **页面没变横向**（Bug）
- A3 纵向 + 反向文字 → 返回 180 → 180° 不交换宽高 → **页面也没变横向**（Bug）
- 带 /Rotate 页（扫描件常见）：`get_text("dict")` 的 dir 处于 **PDF 内部（未旋转）坐标系**，不修正直接用显示坐标判定 → 90°↔270°、0°↔180° 混淆（Bug，本版修复）

### 修复 1：两步法

**优先级 1**：A3 必须横向（短边装订）、A4 必须纵向（长边装订）。
**优先级 2**（文字朝向，在优先级 1 完成后判断）：正面/右面可读 → 不需额外旋转；对面/左面 → 旋转 180°。

实现：
1. 新增 `_rotate_dir(dir, rotation)`：对方向向量施加顺时针旋转（0/90/180/270）。
2. 重写 `detect_text_rotation(page_text_data, must_rotate=False)`：
   - 步骤 1 选基础旋转：`must_rotate` → 90°；否则 → 0°。
   - 步骤 2 对主导文字方向施加基础旋转，结果在正面/右面 → 基础旋转；否则 → 基础旋转 + 180°。
3. `plan_rotation` **对所有页面类型调用** `detect_text_rotation`：A3 横向 / A4 纵向也调用 `must_rotate=False` 检测 180° 倒置（此前直接返回 0）。

### 修复 2：源页 /Rotate 坐标修正（本版新增）

`detect_text_rotation` 新增 `source_rotation: int = 0` 参数：量化前对文字 dir 施加 `_rotate_dir((dx, dy), source_rotation)`，把方向向量从 PDF 内部坐标系变换到**显示坐标系**再做判定。`plan_rotation` 各分支调用时传 `page.source_rotation`。

修正效果（必须改方向场景）：

| /Rotate | 内部 dir | 显示 dir（修正后） | 修正后 | 不修正（旧，错误） |
|---------|----------|--------------------|--------|--------------------|
| 90° | (-1,0) | (0,1) 左面 | **90°** | 270° |
| 90° | (1,0) | (0,-1) 右面 | **270°** | 90° |
| 180° | (1,0) | (-1,0) 对面 | **180°**（not_must） | 0° |
| 180° | (-1,0) | (1,0) 正面 | **0°**（not_must） | 180° |
| 0° | 任意 | 不变 | 与不传一致 | 一致 |

`source_rotation=0` 与不传参数完全一致（向后兼容）；`rotation_cache` key 为 `src_index`，`source_rotation` 是源页固有属性，首次 build 算入缓存即可，无需改缓存逻辑。

### 全部旋转场景对照表（两步法）

**必须改方向的页面（A3 纵向→横向、A4 横向→纵向，基础旋转 = 90°）**

| 原始文字 | dir | 90° 后 | 可读？ | 最终旋转 |
|----------|-----|--------|--------|---------|
| 正面 | (1,0) | (0,-1) 右面 | ✓ | **90°** |
| 左面 | (0,1) | (1,0) 正面 | ✓ | **90°** |
| 对面 | (-1,0) | (0,1) 左面 | ✗ → +180° | **270°** |
| 右面 | (0,-1) | (-1,0) 对面 | ✗ → +180° | **270°** |
| 无文字 | — | — | — | **90°**（默认） |

**不需改方向的页面（A3 横向、A4 纵向、其他尺寸，基础旋转 = 0°）**

| 原始文字 | dir | 可读？ | 最终旋转 |
|----------|-----|--------|---------|
| 正面 | (1,0) | ✓ | **0°** |
| 右面 | (0,-1) | ✓ | **0°** |
| 对面 | (-1,0) | ✗ → +180° | **180°** |
| 左面 | (0,1) | ✗ → +180° | **180°** |
| 无文字 | — | — | **0°** |

**空白页**：继承同纸正面页 `plan[i-1].planned_rotation`（保持不变）。

**用户手动覆盖**：AUTO/CW90/CCW90/ROT180/NONE，覆盖优先级最高（`final_rotation` 不变），即使 ROT180 导致 A3 仍纵向也尊重用户选择。

> 180° 不改变页面尺寸（`_rotated_size` 对 180° 返回原尺寸），不影响空白页继承和布局。

## 二、任务 2：重建性能优化（缓存 + 像素只在扫描页）

### 2.1 三级缓存

| 缓存 | key | 内容 | 清空时机 |
|------|-----|------|---------|
| `_rotation_cache` | `src_index` | `detected_rotation` | 打开新 PDF（`_clear`） |
| `_text_block_cache` | `(src_index, rotation)` | 变换后文本块 bbox 列表 | 打开新 PDF（`_clear`） |
| `_overlap_cache` | `(src_index, 基准位置, 字号, 总旋转, 四边距)` | `(text_hits, pixel_hit, num_rect)` | 打开新 PDF（`_clear`） |

- **旋转检测只依赖源页文本内容**，不随配置变化 → 改配置重建命中缓存跳过 `plan_rotation`/`detect_text_rotation`。
- **文本块 bbox 只依赖 (源页, 旋转角)** → 同一组合结果恒定，命中缓存跳过坐标变换。
- **重叠检测结果依赖 (源页, 页码位置类别, 字号, 总旋转, 四边距)** → 改字号/边距/位置的页 cache_key 变自动重算；`build_process_plan` 新增 `overlap_cache` 可选参数，第一遍检测命中直接复用 `text_hits/pixel_hit`（`num_rect` 用当前计算值），未命中写入缓存；自动调整后的页新结果（含调整后边距的 key）写回缓存。
- 三个缓存都在 `open_pdf` / `_on_async_done` 的 `_clear()` 中清空；**不在改配置时清空**。
- **关键设计**：cache_key 必须含**四边距**。自动调整只移动边距（base/字号/旋转不变），若不含边距，调整后结果与首遍同 key 互相污染（关闭自动调整重建时错误命中"已调整"缓存）。这是实现中发现的正确性坑，已通过在 key 中加入四边距修复。

### 2.2 优化 3：像素检测只在无文本块（扫描页）触发

`_detect_hits` 原逻辑 `if not text_hits and pixel_overlap_checker ...`——**文本块存在但未重叠时也跑像素渲染**，文本 PDF 每页白跑（200 页文本 PDF 190 页白跑）。改为 `if not blocks and pixel_overlap_checker ...`（`blocks`=该页文本块列表，空 = 扫描页才像素检测）。`_rect_overlaps`（auto_adjust_overlap 的 overlap_fn）同步改，自动调整阶段不再每页跑像素渲染。

语义变化：文本页即使像素内容恰好与页码相邻也不报重叠（文本块已覆盖）；**扫描件（无文本块）仍由像素兜底**。

### 2.3 专项测试

- rotation/text_block 缓存：命中不重算（计数 0）、覆盖优先级、开新 PDF 清空、无参数回退。
- overlap_cache：第二次构建命中（text_block_calculator 不再调用）、改字号重算、改边距重算、写入 key 结构。
- 像素优化：扫描页（无文本块）像素命中报重叠；文本页像素被跳过不误报。

### 2.4 实测性能对比（本版实测，Python 3.13 offscreen）

**800 页样本（`sample_800pages.pdf`，每页标题+正文+噪声纹理图）**

| 指标 | v0.5.0（未优化 3/4） | 本版（优化 3 + 4） |
|------|---------------------|-------------------|
| open 冷开 | 6.22s | **3.70s**（-40%） |
| rebuild 缓存命中 | 2.72s | **0.124s**（-95%） |
| rebuild 冷缓存 | 2.78s | **0.169s**（-94%） |

**结论**：v0.5.0 的 rebuild 主要耗时在**未缓存的重叠检测**（800 页 ~2.7s，逐页 `_detect_hits` 文本块遍历 + 像素渲染）。本版通过优化 3（文本页不再跑像素渲染）消除了冷路径的 ~2.6s 像素开销；通过优化 4（overlap_cache）消除了重建路径的 ~2.6s 重叠重算开销。800 页改配置重建从 ~2.7s 降到 **0.12s**。

## 三、任务 3：书视图框选放大

### 实现（适配实际结构）

`book_view.py` 并非滚动式（无 `_scroll_x/_scroll_y/_page_scale`，wheel 翻页、页面始终完整显示）。因此放大**不复用假想的滚动坐标**，改为：

- **状态**：`_zoom_mode`（是否放大模式）、`_rubber_band`（QRubberBand 框选）、`_zoom_rect_widget`（框选区域，widget 坐标）。
- **工具栏按钮**：主窗口 `QToolBar` 新增"放大"（checkable）按钮，`toggled` → `book_view.set_zoom_mode`；双向信号 `zoom_mode_changed` 同步按钮状态（Esc 退出时按钮复位，无死循环）。
- **框选交互**：`mousePressEvent` 开启橡皮筋；`mouseMoveEvent` 更新框选矩形；`mouseReleaseEvent` 若框选 >10×10px 记录为放大区域（<10px 忽略）。
- **渲染**：`paintEvent` 重构出 `_paint_content`；放大模式时先 `fillRect` 背景，再套 painter 变换（`translate` + `scale` 到填满 widget）+ `setClipRect` 后复用原绘制逻辑。**角标（旋/叠/自/空/横）与页码预览随内容一并放大**（满足约束）。
- **退出**：Esc 键或再次点击"放大"按钮退出并清空放大区域。
- **滚动**：放大比例 `min(w/zr.w, h/zr.h)` 保证放大区域恰好填满 widget，无需滚动。

### 专项测试

- `test_zoom_mode_toggle` / `test_zoom_button_syncs_with_view` / `test_zoom_rubber_band_zooms` / `test_zoom_too_small_ignored` / `test_zoom_escape_exits` / `test_zoom_renders_with_pages`。

## 四、任务 4：旋转页重叠自动调整修复

### Bug 背景

原算法 4.5 有 2 行跳过检查：`if (pp.source_page_info.source_rotation + pp.rotation) % 360 != 0: continue`——**旋转页（含源页自带 /Rotate）不自动调整**，仅报重叠警告。

### 修复

删除该跳过检查。依据：`_compute_num_rect` / `_display_anchor` / `_rect_overlaps` / `_move_to_edge` **全在显示坐标系工作**，旋转已由 `output_size_mm`（页面输出尺寸）与 `text_block_calculator` 的 `total_rotation`（源页 /Rotate + 规划旋转）处理，跳过多余。旋转页重叠现走正常移动/缩小流程。

### 附带：旋转页像素检测坐标修正

`detect_pixel_overlap` 用 `page.get_pixmap(clip=...)`，但 clip 是**显示坐标**而 PyMuPDF 默认在**未旋转坐标系**渲染——旋转页 clip 会错位。修复：检测前对 num_rect 施加 `page.derotation_matrix` 变换回未旋转坐标再渲染（旋转页扫描件也正确兜底）。

### 专项测试

- `TestRotationAdjusted.test_rotated_page_adjusted`：planned_rotation=90（A4 横向→纵向）→ 旋转页**触发**自动调整（overlap_adjusted=True、warnings 空）——原 `TestRotationSkip`（跳过+保留警告）反转。

## 五、任务 5：配置文件持久化计算结果

### 方案

配置文件 `*.pagerconfig.json` 新增 `computed` 段（与 `global`/`pages` 平级，`CONFIG_VERSION` 不变仍为 2）：

```json
"computed": {
  "rotations": {"0": 90, "1": 0},
  "overlap": {
    "fingerprint": "9.0|10.0|10.0|10.0|10.0|bottom|true|2|1",
    "entries": [{"key": [0, "bottom_right", 9.0, 0, 10.0, 10.0, 10.0, 10.0],
                 "text_hits": [], "pixel_hit": false, "num_rect": [...]}]
  }
}
```

- **`save_all`** 新增 `rotation_cache` / `overlap_cache` / `overlap_fingerprint` 可选参数，写入 `computed` 段。
- **`load_computed(pdf_path, current_fingerprint, source_pages=None)`**：`rotations` 只依赖源页内容，`source_file` 匹配即有效（跨配置复用）；`overlap` 需指纹一致才返回。
- **指纹 `_overlap_fingerprint(config)`** = 全局样式（字号/四边距/垂直位置）+ `auto_adjust_overlap`/`auto_shrink_levels` + `start_page_number` 拼接。任一变化 → 指纹变 → 旧 overlap 缓存视为失效（不预热）。
- **单页覆盖过滤**：有 `style_override` 或 `number_pos_override` 的页不预取重叠缓存（实际生效样式与全局指纹不一致）。
- **约束满足**：旧配置无 `computed` 段正常加载；`computed` 损坏不影响 `global/pages`。
- **app_controller**：`open_pdf` / `_on_async_done` 清空三缓存后 `_prewarm_computed()` 预热；`_do_save_config` 保存时写入 `computed`。

### 专项测试

- `test_roundtrip_rotation_and_overlap`：save → load 完整还原。
- `test_fingerprint_mismatch_no_overlap`：指纹变（字号改）→ overlap 不预热，rotation 仍有效。
- `test_override_page_not_prefetched`：单页覆盖的页不预取。
- `test_missing_computed_ok` / `test_corrupted_computed_ok`：缺失/损坏不影响加载。
- `TestControllerPersistPrewarm.test_save_then_reopen_prewarms`：端到端——保存写入 → 重开预热，缓存一致。
