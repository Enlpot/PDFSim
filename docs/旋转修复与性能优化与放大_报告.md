## 一、任务 1：旋转方向修复（两步法）

### Bug 背景

原 `detect_text_rotation` 只考虑"让文字 dir 变成 (1,0)"，不区分"页面是否必须旋转"，导致：

- A3 纵向 + 水平文字 → 返回 0 → 不旋转 → **页面没变横向**（Bug）
- A3 纵向 + 反向文字 → 返回 180 → 180° 不交换宽高 → **页面也没变横向**（Bug）

### 修复：两步法

**优先级 1**：A3 必须横向（短边装订）、A4 必须纵向（长边装订）。
**优先级 2**（文字朝向，在优先级 1 完成后判断）：正面/右面可读 → 不需额外旋转；对面/左面 → 旋转 180°。

实现：
1. 新增 `_rotate_dir(dir, rotation)`：对方向向量施加顺时针旋转（0/90/180/270）。
2. 重写 `detect_text_rotation(page_text_data, must_rotate=False)`：
   - 步骤 1 选基础旋转：`must_rotate` → 90°；否则 → 0°。
   - 步骤 2 对主导文字方向施加基础旋转，结果在正面/右面 → 基础旋转；否则 → 基础旋转 + 180°。
   - `must_rotate` 参数默认 `False`（向后兼容）。
3. `plan_rotation` **对所有页面类型调用** `detect_text_rotation`：A3 横向 / A4 纵向也调用 `must_rotate=False` 检测 180° 倒置（此前直接返回 0）。

### 全部旋转场景对照表

**必须改方向的页面（A3 纵向→横向、A4 横向→纵向，基础旋转 = 90°）**

| 原始文字 | dir | 90° 后 | 可读？ | 最终旋转 |
|----------|-----|--------|--------|---------|
| 正面 | (1,0) | (0,-1) 右面 | ✓ | **90°** |
| 左面 | (0,1) | (1,0) 正面 | ✓ | **90°** |
| 对面 | (-1,0) | (0,1) 左面 | ✗ → +180° | **270°** |
| 右面 | (0,-1) | (-1,0) 对面 | ✗ → +180° | **270°** |
| 无文字 | — | — | — | **90°**（默认） |

**不需改方向的页面（A3 横向、A4 纵向、其他尺寸，基础旋转 = 0°）**

| 原始文字 | dir | 可读？ | 最终旋转 |
|----------|-----|--------|---------|
| 正面 | (1,0) | ✓ | **0°** |
| 右面 | (0,-1) | ✓ | **0°** |
| 对面 | (-1,0) | ✗ → +180° | **180°** |
| 左面 | (0,1) | ✗ → +180° | **180°** |
| 无文字 | — | — | **0°** |

**空白页**：继承同纸正面页 `plan[i-1].planned_rotation`（保持不变）。

**用户手动覆盖**：AUTO/CW90/CCW90/ROT180/NONE，覆盖优先级最高（`final_rotation` 不变），即使 ROT180 导致 A3 仍纵向也尊重用户选择。

> 180° 不改变页面尺寸（`_rotated_size` 对 180° 返回原尺寸），不影响空白页继承和布局。

## 二、任务 2：重建性能优化（缓存）

### 方案

| 缓存 | key | 内容 | 清空时机 |
|------|-----|------|---------|
| `_rotation_cache` | `src_index` | `detected_rotation` | 打开新 PDF（`_clear`） |
| `_text_block_cache` | `(src_index, rotation)` | 变换后文本块 bbox 列表 | 打开新 PDF（`_clear`） |

- **旋转检测只依赖源页文本内容**，不随配置变化 → 改配置重建命中缓存跳过 `plan_rotation`/`detect_text_rotation`。
- **文本块 bbox 只依赖 (源页, 旋转角)** → 同一组合结果恒定，命中缓存跳过坐标变换。
- 两个缓存都在 `open_pdf` / `_on_async_done` 的 `_clear()` 中清空；**不在改配置时清空**。
- `build_process_plan` 新增可选参数 `rotation_cache`（默认 None，不传行为不变）；算法 3 命中缓存直接复用 `detected_rotation`，`final_rotation`（用户覆盖）仍在命中路径应用。

### 专项测试

- `test_rotation_cache_hit`：monkeypatch 计数 `plan_rotation`，第二次 build 命中缓存 → 0 次重算；两次规划结果一致。
- `test_rotation_cache_respects_override`：缓存存 `detected_rotation`，用户覆盖在 `final_rotation` 生效（检测 90 → 覆盖 NONE → 0）。
- `test_no_cache_param_fallback`：不传 `rotation_cache` 每次重算（行为不变）。
- `test_text_block_cache_hit`：同 (源页, 旋转角) 二次调用命中缓存（同一对象）。
- `test_text_block_cache_keyed_by_rotation`：不同旋转角 → 不同缓存条目。
- `test_open_new_pdf_clears_caches`：打开新 PDF 清空（fake 索引 999 不残留）。

### 实测性能对比

本机（Python 3.13，offscreen）：

**200 页样本（`sample_200pages.pdf`）**
```
rebuild 缓存命中 #1: 0.075s    （rotation_cache=200, text_block_cache=200）
rebuild 缓存命中 #2: 0.072s
rebuild 冷缓存(新PDF) #1: 0.086s
rebuild 冷缓存(新PDF) #2: 0.082s
```
缓存命中较冷缓存快约 **13%**。

**800 页样本（`sample_800pages.pdf`）**
```
rebuild 缓存命中 #1: 2.719s
rebuild 缓存命中 #2: 2.770s
rebuild 冷缓存   #1: 2.777s
rebuild 冷缓存   #2: 2.815s
```
缓存命中较冷缓存快约 **2%**。

**结论（如实说明）**：两个缓存均已实现并通过"不重算"断言验证（`plan_rotation` 计数为 0）。但实测整体收益有限（200 页 +13% / 800 页 +2%），因为 rebuild 的主要耗时在**未缓存的重叠检测**（`detect_overlap` 文本块遍历 + 像素检测，逐页必跑）。按提示语指导者建议，优化 3（跳过未变页重叠检测，按 `(src_index, num_rect, fontsize)` 缓存）**复杂度高，第一版可不做**——作为后续优化项，收益最大。

## 三、任务 3：书视图框选放大

### 实现（适配实际结构）

`book_view.py` 并非滚动式（无 `_scroll_x/_scroll_y/_page_scale`，wheel 翻页、页面始终完整显示）。因此放大**不复用假想的滚动坐标**，改为：

- **状态**：`_zoom_mode`（是否放大模式）、`_rubber_band`（QRubberBand 框选）、`_zoom_rect_widget`（框选区域，widget 坐标）。
- **工具栏按钮**：主窗口 `QToolBar` 新增"放大"（checkable）按钮，`toggled` → `book_view.set_zoom_mode`；双向信号 `zoom_mode_changed` 同步按钮状态（Esc 退出时按钮复位，无死循环）。
- **框选交互**：`mousePressEvent` 开启橡皮筋；`mouseMoveEvent` 更新框选矩形；`mouseReleaseEvent` 若框选 >10×10px 记录为放大区域（<10px 忽略）。
- **渲染**：`paintEvent` 重构出 `_paint_content`；放大模式时先 `fillRect` 背景，再套 painter 变换（`translate` + `scale` 到填满 widget）+ `setClipRect` 后复用原绘制逻辑。**角标（旋/叠/自/空/横）与页码预览随内容一并放大**（满足约束）。
- **退出**：Esc 键或再次点击"放大"按钮退出并清空放大区域（右键未单独实现，Esc/按钮已覆盖提示语退出方式）。
- **滚动**：放大比例 `min(w/zr.w, h/zr.h)` 保证放大区域恰好填满 widget，无需滚动（约束满足）。

### 专项测试

- `test_zoom_mode_toggle`：按钮切换进入/退出放大模式，退出清空区域。
- `test_zoom_button_syncs_with_view`：视图侧切换与按钮状态同步（信号双向不循环）。
- `test_zoom_rubber_band_zooms`：框选后 `zoom_rect()` 记录区域，放大渲染不崩溃。
- `test_zoom_too_small_ignored`：<10px 框选忽略。
- `test_zoom_escape_exits`：Esc 退出并复位按钮。
- `test_zoom_renders_with_pages`：有页面（打开样本）时框选放大渲染不崩溃（覆盖角标/页码预览路径）。

## 八、遗留与后续建议

1. **性能优化 3（跳过未变页重叠检测）**：当前 rebuild 主要耗时在重叠检测（800 页 ~2.7s），提示语标注为可选。若后续用户反馈大文档改配置卡顿，建议按 `(src_index, num_rect_pt, fontsize_pt)` 缓存重叠结果，收益最大。
2. 放大模式坐标基于 widget 坐标（书视图非滚动式），若未来书视图改为可滚动，需重新接入内容坐标换算。
