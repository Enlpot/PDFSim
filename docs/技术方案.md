## 1. 系统架构设计

### 1.1 模块划分

按提示语要求划分 7 个模块：

| 模块 | 技术载体 | 核心职责 |
|------|----------|----------|
| **加载模块**（Loader） | pikepdf / PyMuPDF | 打开 PDF、检测损坏/加密、解密、读取页数、读取书签（Outline）、读取每页尺寸与方向、读取配置恢复 |
| **标记模块**（Marker） | 纯 Python | 维护页面标记集合（封面/签字页/不加页码/不占序号/从正面开始/自定义标签）、自动识别书签关键词、手工标记覆盖 |
| **算法引擎**（Engine） | 纯 Python | 执行 5 大核心算法：物理顺序规划、页码规划、页面旋转、页码坐标计算、重叠检测判定 |
| **渲染模块**（Renderer） | PyMuPDF | 缩略图渲染（`page.get_pixmap()`）、书视图渲染、文字重叠检测的文本块坐标提取（`page.get_text("dict")`）、页码文字绘制（`page.insert_text()`） |
| **输出模块**（Output） | pikepdf / PyMuPDF | 构建结构副本（复制页/插空白页/旋转）、追加页码内容流、保存输出文件、输出存在性检查 |
| **配置模块**（Config） | JSON / 纯 Python | `.pagerconfig.json` 的读写、默认参数管理、配置恢复 |
| **UI 模块**（UI） | PySide6 | 主窗口、书视图、缩略图面板、页面配置面板、全局设置对话框、异常弹窗、交互状态管理（详见《UI原型说明.md》） |

### 1.2 模块间数据流向（文字描述）

```
                    ┌──────────────────────────────────────────────────┐
                    │                    UI 模块 (PySide6)              │
                    │  主窗口 / 书视图 / 缩略图 / 配置面板 / 对话框      │
                    └───┬───────────┬──────────────┬───────────┬───────┘
                        │ ①打开请求   │ ⑦渲染请求    │ ⑨标记/设置  │ ⑪输出请求
                        ▼           │              ▼           ▼
     ┌──────────────┐  │ ②原始页信息 │            ┌──────────────┐
     │  加载模块     │──┘            │            │  算法引擎     │
     │  打开/解密/   │ ③书签→自动标记 │            │  ①物理顺序    │
     │  尺寸/书签    │              ▼            │  ②页码规划    │
     └──────────────┘        ┌──────────┐       │  ③旋转决策    │
                             │  标记模块 │◄──────│  ④坐标计算    │
                             └──────────┘       │  ⑤重叠判定    │
                                                   └──────┬───────┘
                                                          │ ⑧处理结果模型
                    ┌──────────────┐  ⑨配置存取  ┌────────┴───────┐
                    │  配置模块     │◄───────────┤  渲染模块       │
                    │ .pagerconfig │            │  缩略图/书视图/  │
                    └──────────────┘            │  重叠提取/绘字  │
                                               └────────┬───────┘
                                                        │ ⑩绘制请求
                                               ┌────────┴───────┐
                                               │  输出模块       │
                                               │  结构副本→绘页码│
                                               └────────────────┘
```

关键流程描述（Step ①–⑪）：

1. **①打开请求**：UI 触发 → 加载模块打开 PDF。打开期间完成：损坏检测、加密检测（需弹窗输密码）、页数检查（0 页退出）、读取每页尺寸/方向/自带旋转、读取书签。
2. **②原始页信息**：加载模块把每页的 `PageInfo`（原始索引、尺寸、方向、自带旋转角、内容为空与否）交给 UI 与算法引擎。
3. **③书签→自动标记**：加载模块用书签关键词生成初始标记建议，交给标记模块；标记模块维护"自动标记 + 手工标记"两层，手工优先。
4. **⑤标记/设置**：用户在 UI 上修改标记、页码样式、起始页码、每页位置覆盖等，实时写入标记模块与配置模块。
5. **⑦渲染请求**：UI 每次需要缩略图/书视图画面时向渲染模块请求；渲染模块依据"物理顺序模型"对原页（含旋转）或空白占位进行渲染。
6. **⑧处理结果模型**：算法引擎根据标记与原始页信息，产出 `ProcessedPage` 列表（物理顺序、页码数字、页码坐标、旋转角、空白类型），作为输出与预览的唯一依据。
7. **⑨配置存取**：配置模块在打开时加载同名 `.pagerconfig.json`（若存在）恢复状态；在标记/设置变更时自动保存。
8. **⑩绘制请求 → ⑪输出请求**：输出模块先由 pikepdf 构建结构副本（复制页→插空白→旋转），再由 PyMuPDF 在副本上按坐标绘制页码文字，最后落盘为 `原文件名（打印装订）.pdf`。

**核心约束**：所有对 PDF 的操作都发生在"原文件副本"上；原文件在加载后以只读方式引用，任何模块不得写回原路径。

### 1.3 模块职责边界（杜绝越界）

| 边界 | 规则 |
|------|------|
| 渲染 vs 输出 | 渲染模块只读（渲染缩略图、提取文本块坐标、为预览生成画面）；输出模块才写（构建结构副本、绘制页码、落盘）。渲染模块**永不保存文件**。 |
| 算法引擎 vs 渲染 | 算法引擎只做纯计算（不调用 PDF 库），输出 `ProcessedPage` 模型；渲染/输出模块只按模型执行，不在自身做业务决策。 |
| pikepdf vs PyMuPDF | 见 5.1：结构操作（复制/插空白/旋转）只用 pikepdf；渲染/绘制/重叠提取只用 PyMuPDF，两者不混用同一功能。 |
| 加载 vs 输出 | 加载模块打开的 `Pdf` 句柄在输出前可复用（避免二次 IO），但输出模块写入的是新副本，绝不触碰加载句柄的源文件。 |

## 2. 核心数据结构设计

以下结构全部用 Python 类型注解定义，作为 Stage 2 实现的接口契约。所有物理顺序索引均为 **1-based**（与提示语"第 1 页、第 2 页……"表述一致），PDF 页面对应关系在模型层使用 0-based 原始索引并显式标注。

### 2.1 页面标记枚举 `PageMark`

```python
from enum import Enum

class PageMark(str, Enum):
    """页面标记（可多选）。

    规则变更（《多选批量与空白页配置_提示语》0.1）："不加页码"新语义——
    保留内容、不显示页码数字、序号跳过（后续页码顺延前移）。
    """
    COVER      = "cover"      # 封面
    SIGNATURE  = "signature"  # 签字页
    NO_NUMBER  = "no_number"  # 不加页码：保留内容，不显示页码数字，序号跳过（新语义）
    NO_COUNT   = "no_count"   # 已废弃（用户标记路径废除）：旧"不占序号"=丢弃内容+不占序号，
    #                          违反内容保护铁律；旧配置迁移为 NO_NUMBER，不再产生
    FRONT      = "front"      # 从正面开始（目标页须落在纸张正面=物理奇数位）
    # 用户自定义标签：仅展示标记，不产生自动行为（见 DocumentConfig.custom_labels）
```

> 规则变更（用户批准，见《规则变更与批量配置_报告.md》）：
> - `NO_COUNT`（不占序号）用户标记路径**废除**——旧语义"原页变空白（内容丢弃）"违反**内容保护铁律**（只允许添加页码/插入空白页/旋转页面，禁止删除或隐藏原页面）。
> - 旧配置中 `no_count` 标记加载时**迁移为 `NO_NUMBER`**（行为变为：保留内容 + 无页码 + 跳过序号）。
> - `NO_NUMBER` 新语义：保留内容、无页码数字、**跳过序号**（旧"占序号但不显示"废弃）。

### 2.2 空白页来源枚举 `BlankPageSource`

```python
class BlankPageSource(str, Enum):
    """空白页的来源类型（决定尺寸、是否有页码、是否占序号）。"""
    COVER_BACK    = "cover_back"     # 封面背面     ：与封面同尺寸，有页码，占序号
    SIGN_BACK     = "sign_back"      # 签字页背面   ：与签字页同尺寸，无页码，不占序号
    NO_COUNT_USER = "no_count_user"  # 已废弃（旧"不占序号"用户标记产物，不再产生；保留枚举供序列化兼容）
    PUSH_FRONT    = "push_front"     # 推动某页到正面：与相邻页同尺寸，有页码，占序号
    A3_BACK       = "a3_back"        # A3 页背面     ：与该 A3 页同尺寸，无页码，不占序号
    FILL_LAST     = "fill_last"      # 补齐末页     ：与最后一页同尺寸，有页码，占序号
```

> 空白页**默认**页码行为由来源类型决定（A3 背面/签字页背面不占序号等），
> 用户可对空白页显式设"不加页码"**覆盖默认**（覆盖优先级：用户显式标记 > 来源默认）。

`BlankPageSource` 直接映射提示语 6.2 空白页插入规则表，**禁止出现表外类型**。

### 2.4 单页信息 `PageInfo`

```python
from dataclasses import dataclass, field

@dataclass
class PageInfo:
    """
    单页信息。一个 PageInfo 对应"一个物理页面"（既包括原页，也包括自动插入的空白页）。
    """
    original_index: int | None            # 原始 PDF 页索引（0-based）；空白页为 None
    width_mm: float                       # 页面物理宽度（mm，按显示尺寸；已计入源页自带 /Rotate）
    height_mm: float                      # 页面物理高度（mm）
    source_rotation: int                  # 源页自带的 /Rotate（0/90/180/270），加载时读取，输出时保留
    detected_rotation: int = 0            # 文字方向检测结果（0/90/270，问题 3 修改；算法 3 填充）
    planned_rotation: int = 0             # 最终旋转角（受 rotation_override 影响；0/90/270）
    rotation_override: RotationOverride = RotationOverride.AUTO  # 旋转方向覆盖（问题 3 修改）
    marks: set[PageMark] = field(default_factory=set)      # 页面标记集合（可多选）
    custom_labels: list[str] = field(default_factory=list) # 用户自定义标签（仅展示）
    is_blank: bool = False                # 是否为空白页
    blank_source: BlankPageSource | None = None  # 空白页来源类型；非空白页为 None
    number_pos_override: PageNumberPos | None = None  # 页码位置单页覆盖；None=沿用全局
    number_custom_offset_mm: tuple[float, float] | None = None  # 自定义页码偏移(x,y)（mm）
    style_override: "PageNumberStyle | None" = None  # 页码样式单页覆盖；None=沿用全局
```

## 3. 核心算法设计

### 3.1 算法 1：物理顺序规划算法

**输入**：原始页面列表（含每页标记）+ 文档配置（自动补齐末页开关）。
**输出**：按物理顺序排列的页面列表（含插入的空白页）。
**约定**：物理顺序为 1-based；**每插入一次，后续页面物理顺序即重排一次**（所有下游判定都基于新顺序）。

> 规则变更：~~"不占序号"页替换为空白页~~ **已删除**。原页一律保留内容（内容保护铁律），
> 旧 `NO_COUNT` 标记加载时迁移为 `NO_NUMBER`（保留内容 + 无页码 + 跳过序号）。

#### 3.1.1 处理规则映射（严格对照提示语 6.2 / 6.3）

| 场景 | 动作 | 空白页特征 | 尺寸 | 页码 | 占序号 |
|------|------|-----------|------|------|--------|
| 原页标记"不加页码"（NO_NUMBER） | **保留原页**（不删除、不替换） | — | — | 无 | **跳过**（新语义，后续顺延前移） |
| 目标页须"从正面开始"且当前处于偶数位 | **在其前面插入空白页** | 空白 | 与相邻页（**前一页**）同尺寸（D5） | 有 | 占 |
| 封面页 | **在其后插入空白页（封面背面）** | 空白 | 与封面同尺寸 | 有 | 占 |
| 签字页 | **在其后插入空白页（签字页背面）** | 空白 | 与签字页同尺寸 | 无 | 不占 |
| A3 页 | **在其后插入空白页（A3 背面）**；同时 A3 页"从正面开始"为只读（需求要点 3-边界；算法上 `is_a3(p)` 等同 FRONT） | 空白 | 与该 A3 页同尺寸 | 无 | 不占 |
| 补齐末页（用户可选，默认否） | 若最后一页为奇数位，**末尾追加空白页** | 空白 | 与最后一页同尺寸 | 有 | 占 |

> **空白页可配置**（任务 2）：用户可对自动插入的空白页显式设"不加页码"，
> 覆盖来源默认（如封面背面默认有页码 → 改为无页码+跳过序号）。
> 空白页有跨 rebuild 稳定的标识 `blank_id = f"blank:{触发源标识}:{来源类型}"`。

#### 3.1.2 算法描述

**标记联动（问题 1 修改）**：封面/签字页的"从正面开始"通过**标记联动**实现，而非在 `need_front` 中额外判断：
- 自动识别：命中封面关键词 → 同时标记 `COVER` + `FRONT`；命中签字关键词 → 同时标记 `SIGNATURE` + `FRONT`（见 2.6 说明与 UI 说明 7.2）。
- 手工标记：UI 勾选"封面"时自动勾选"从正面开始"（可取消）；勾选"签字页"同理（见 UI 说明 4.1）。
- 因此 `need_front` **只检查 `FRONT`**（A3 的 FRONT 只读），保证用户取消 `FRONT` 后该页不再强制从正面开始（A3 除外，符合需求 6.3）。

```
输入: source_pages   # 原始页列表（顺序即源 PDF 页序）
      config         # DocumentConfig（含 auto_fill_last_page）

# 判断“该页是否必须从正面开始”：
#   只检查 FRONT 标记；A3 页的 FRONT 标记为只读置灰（见 UI 说明），算法上等同 FRONT。
#   封面/签字页的 FRONT 由【标记联动】保证（见上方说明），此处无需再检查 COVER/SIGNATURE。
def need_front(p): return (PageMark.FRONT in p.marks) or is_a3(p)

plan = []  # 物理顺序列表（元素为 PageInfo；空白页 is_blank=True）

for p in source_pages:
    # ① “从正面开始”检查：当前 plan 长度即本页将落位的物理序号
    #    物理序号为偶数（背面）时，先插一张空白页把它推到奇数位（正面）
    if need_front(p) and (len(plan) + 1) % 2 == 0:
        plan.append(make_blank(size=adjacent_size(plan, p), source=PUSH_FRONT,
                               blank_id=make_blank_id(p, PUSH_FRONT)))

    # ② 放入原页（内容保护铁律：原页一律保留内容，不删除不替换）
    plan.append(p)

    # ③ 封面/签字页/A3 背面空白（在刚放入的页之后立即插入）
    if PageMark.COVER in p.marks and not is_a3(p):
        plan.append(make_blank(size=p.size, source=COVER_BACK,
                               blank_id=make_blank_id(p, COVER_BACK)))
    elif PageMark.SIGNATURE in p.marks and not is_a3(p):
        plan.append(make_blank(size=p.size, source=SIGN_BACK,
                               blank_id=make_blank_id(p, SIGN_BACK)))
    if is_a3(p):
        plan.append(make_blank(size=p.size, source=A3_BACK,
                               blank_id=make_blank_id(p, A3_BACK)))
    # D6：若同一页既是封面/签字页又是 A3，A3 背面规则优先（仅插一张，按 A3 背面：无页码不占序号）

# ⑤ 补齐末页
if config.auto_fill_last_page and len(plan) % 2 == 1:
    last = plan[-1]
    plan.append(make_blank(size=last.size, source=FILL_LAST,
                           blank_id=make_blank_id(None, FILL_LAST)))

# ⑥ 空白页用户配置：build_process_plan(blank_configs) 在算法 1 之后应用
#    blank_configs: dict[blank_id, set[PageMark]]——用户显式标记覆盖来源默认
return plan
```

#### 3.1.3 级联处理逻辑（提示语 3.4 的工程化）

提示语要求"先处理从正面开始 → 再处理封面/签字页/A3 背面 → 每次插入后物理顺序重排"。经分析（见 D4），**严格的两阶段顺序在级联插入下不能保证正确**：

- 例：先修好"从正面开始"页 X（插空白推到奇数位），随后在其**前面**再插入封面背面空白，会把 X 重新推到偶数位，破坏刚满足的"正面"约束。

因此本方案采用 **单趟正向累加**：按源页顺序逐页处理，每页落位时都基于"当前 plan 长度"（即已包含此前所有插入的最新物理顺序）做奇偶判定，从而天然满足"每次插入后物理顺序重排"且一次遍历即收敛。**该顺序同时满足"每页先判正面、再补背面"的局部语义**，是本算法对提示语处理顺序的规范化实现（请指导者确认，见 D4）。

### 3.2 算法 2：页码规划算法

**输入**：物理顺序列表 `plan` + 起始页码 + 各页标记/空白类型 + 空白页用户配置。
**输出**：每页的页码数字（`number_text`，无页码为 `None`）与是否占序号（`number_occupies`）。

> 规则变更（《多选批量与空白页配置_提示语》0.1）：
> `NO_NUMBER` 新语义 = 保留内容 + 无数字 + **跳过序号**（后续页码顺延前移）。
> 旧 `NO_COUNT` 残留标记按 `NO_NUMBER` 防御等价（加载迁移后不应再出现）。

```
seq = config.start_page_number
for page in plan:                      # 按物理顺序遍历
    if page.is_blank:
        # 空白页：默认按来源类型；用户显式"不加页码"覆盖（见空白页配置）
        if PageMark.NO_NUMBER in page.marks or blank_configs.get(page.blank_id, set()):
            page.number_text = None;  page.number_occupies = False   # 跳过序号
        elif page.blank_source in (SIGN_BACK, A3_BACK):              # 来源默认：无页码不占序号
            page.number_text = None;  page.number_occupies = False
        else:  # COVER_BACK / PUSH_FRONT / FILL_LAST 默认有页码占序号
            page.number_text = str(seq);  page.number_occupies = True
            seq += 1
    elif PageMark.NO_NUMBER in page.marks or PageMark.NO_COUNT in page.marks:
        # 不加页码（含残留 NO_COUNT 防御等价）：保留内容，无数字，跳过序号
        page.number_text = None;  page.number_occupies = False
    else:
        page.number_text = str(seq);  page.number_occupies = True
        seq += 1
```

**要点**：
- 页码数字**只决定显示什么**，不决定位置；位置由物理奇偶决定（见算法 4）。
- "不加页码"页（含空白页显式覆盖）跳过序号不递增 → 其后的页页码数字与物理顺序不一致（顺延前移，提示语 0.1 示例：页1"1"、页2无、页3"2"）。
- A3 页本身是普通"有页码占序号"页，只是位置固定右下角。

### 3.3 算法 3：页面旋转算法

**输入**：原页面显示尺寸（宽×高，mm；已计入源页自带 /Rotate）+ 页面文字方向（PyMuPDF 提取）。
**输出**：检测旋转角 `detected_rotation`（0° / 90° / 270°）+ 旋转后尺寸；最终旋转角 `planned_rotation` 由 `rotation_override` 决定（见 3.3.3）。

#### 3.3.1 判定表（严格对照提示语 5.2）

| 源页显示尺寸（mm） | 判定方向 | 是否需旋转 | 旋转方向 | 旋转后尺寸（mm） | 装订边 | 页码位置 |
|--------------------|----------|------------|----------|------------------|--------|----------|
| ≈210 × 297（A4 纵向） | 纵向 | 不旋转 | — | 210 × 297 | 长边 297 | 物理奇/偶 → 右下/左下 |
| ≈297 × 210（A4 横向） | 横向 | **需旋转** | 文字方向检测（90° 或 270°，问题 3 修改） | 210 × 297 | 长边 297 | 物理奇/偶 → 右下/左下 |
| ≈297 × 420（A3 纵向） | 纵向 | **需旋转** | 文字方向检测（90° 或 270°，问题 3 修改） | 420 × 297 | 短边 297 | 固定右下角 |
| ≈420 × 297（A3 横向） | 横向 | 不旋转 | — | 420 × 297 | 短边 297 | 固定右下角 |
| 其他尺寸（如 Letter） | —— | 不旋转 | —（D3：按物理奇偶放页码） | 原尺寸 | —— | 物理奇/偶 → 右下/左下 |

- 尺寸匹配带容差（D7：±2mm；mm 与 point 的换算见算法 4）。
- 旋转方向由**文字方向检测**决定（见 3.3.2），并在 UI 中标注、允许用户覆盖（`RotationOverride`，见 UI 说明 4.3）。
- 旋转实现：pikepdf `page.rotate(90|270)`（按最终旋转角调用）。pikepdf `page.rotate()` 的实际旋转方向（`/Rotate` 语义）在 Stage 2 用方向标记样本验证（见《Stage1 审查报告》"二、需 Stage 2 验证的技术点"）。

#### 3.3.2 文字方向检测与旋转方向判定（问题 3 修改）

**可读性标准（提示语 5.3）**：装订成书后，读者站在书的右侧，将书**逆时针旋转 90°** 后能正常阅读。

**检测目标**：对需旋转页（A4 横向、A3 纵向），求出使"读者把书逆时针转 90° 后文字正立"的旋转角（90° 或 270°）。

**检测方法（PyMuPDF）**：
1. 提取页面文字方向信息：`page.get_text("dict")` 中每个文本 block/line 的 `dir` 字段（基线方向向量），或 `page.get_texttrace()`（更高阶的字符级方向）。
2. 统计正文文字的主导方向（按文本量加权）：忽略极小/角标文本，取占比最大的基线方向。
3. 由主导方向推导旋转角：
   - 正文基线为"横向正读"（沿页面宽方向、左→右）→ 需旋转 **90°（顺时针）**，`detected_rotation = 90`；
   - 正文基线本身已处于其他方向（如源页已带旋转/方向特殊）→ 按"逆时针转书 90° 后可读"反推，得到 **270°（逆时针）**，`detected_rotation = 270`；
   - 页面无文字/文字极少（纯图片页）→ 无法可靠检测，**回退默认 90°** 并提示用户在 UI 中确认。
4. 检测结果写入 `PageInfo.detected_rotation`；用户可用 `rotation_override` 覆盖为最终 `planned_rotation`（见 3.3.3 与 UI 说明 4.3）。

> 说明：A3 横向、A4 纵向不旋转，无需检测；`detected_rotation` 记为 0。

#### 3.3.3 旋转伪代码

```
# 文字方向检测：返回 0/90/270（0=无需旋转；90=顺时针 90°；270=逆时针 90°）
def detect_text_rotation(page: PageInfo) -> int:
    blocks = page.get_text("dict")["blocks"]
    dirs = 统计各文本 block/line 的 dir 向量（按文本量加权）
    dominant = 取占比最大的基线方向
    if 无有效文本:  return 90                    # 回退默认（UI 提示确认）
    return rotation_from_baseline(dominant)      # 按 3.3.2 反推 90 或 270

def plan_rotation(page: PageInfo) -> tuple[int, (w_mm, h_mm)]:
    w, h = page.width_mm, page.height_mm
    if approx(w, 297) and approx(h, 420):   # A3 纵向 → 需旋转
        r = detect_text_rotation(page)
        page.detected_rotation = r
        return r, (420, 297)
    if approx(w, 420) and approx(h, 297):   # A3 横向 → 不旋转
        page.detected_rotation = 0
        return 0, (420, 297)
    if approx(w, 297) and approx(h, 210):   # A4 横向 → 需旋转
        r = detect_text_rotation(page)
        page.detected_rotation = r
        return r, (210, 297)
    if approx(w, 210) and approx(h, 297):   # A4 纵向 → 不旋转
        page.detected_rotation = 0
        return 0, (210, 297)
    page.detected_rotation = 0
    return 0, (w, h)                        # 其他尺寸不旋转（D3）

# 最终旋转角（问题 3 修改）：用户可用 rotation_override 覆盖自动检测结果
def final_rotation(page: PageInfo) -> int:
    o = page.rotation_override              # auto / cw90 / ccw90 / none
    if o == "auto":  return page.detected_rotation
    if o == "cw90":  return 90
    if o == "ccw90": return 270
    if o == "none":  return 0               # 不旋转（仅用户显式选择）
    # 返回的角在输出阶段用 pikepdf page.rotate(angle, relative=True) 叠加到源 /Rotate
```

### 3.4 算法 4：页码坐标计算算法

**输入**：旋转后页面尺寸 + 物理顺序（奇偶）+ 页码样式 + 位置设置（全局/单页覆盖）。
**输出**：页码文字在 **PDF 未旋转坐标系**中的绘制点 (x, y)（单位 point）。
**坐标系**：PDF 原点在左下角；1 mm ≈ 72/25.4 ≈ **2.8346 pt**。

#### 3.4.1 步骤

```
1. 确定“显示坐标系”（旋转后页面）中的目标角：
   - A3 页                → 右下角
   - 物理奇数页（正面）    → 右下角
   - 物理偶数页（背面）    → 左下角
   - 单页 CUSTOM 覆盖     → 按用户偏移 (dx_mm, dy_mm) 相对上述基准角定位

2. 文字宽度（pt）：
   text_w = font.text_length(number_text, fontsize=fontsize_pt)
   # PyMuPDF: fitz.Font("times").text_length(...)；嵌入字体时用同一 Font 对象

3. 边距（mm → pt）：right_pt = margin_right_mm*2.8346；left_pt = margin_left_mm*2.8346
   bottom_pt = margin_bottom_mm*2.8346

4. 在“显示坐标系”中计算基准点（旋转后页宽 W、高 H，pt）：
   - 右下角：anchor = (W - right_pt - text_w, bottom_pt)
   - 左下角：anchor = (left_pt, bottom_pt)
   - 自定义：在所选基准角基础上 ±(dx_mm*2.8346, dy_mm*2.8346)（方向由 UI 约定，见 UI 说明 4.4）

5. 坐标系换算（关键）：
   PyMuPDF 的 insert_text / get_text 均基于“未旋转坐标系”（见 5.3）。
   若该页规划旋转角 r ≠ 0，则把显示坐标 anchor 经 Page.derotation_matrix
   变换为未旋转坐标 p0：
       p0 = anchor * page.derotation_matrix
   若 r = 0：p0 = anchor

6. 输出：p0 = (x, y)（pt，作为 insert_text 的 point 参数）
```

**设计要点**：页码位置"基于旋转后的物理页面"（提示语 5.4）→ 坐标先在**显示坐标系**按旋转后页宽高计算；再用 `derotation_matrix` 映射到 PyMuPDF 要求的**未旋转坐标系**绘制。这样页码会正确落在旋转后页面的目标角，且与旋转后的内容方向一致。

### 3.5 算法 5：重叠检测算法

**输入**：页码矩形区域（显示坐标 pt）+ 原页面文本块坐标列表。
**输出**：是否重叠 + 重叠区域。

```
1. 计算页码文字矩形（显示坐标系，pt）：
   # 用算法4的锚点与文字宽高推算包围盒
   num_rect = rect_from_anchor(anchor, text_w, fontsize_pt)

2. 提取该页文本块 bbox（PyMuPDF）：
   blocks = page.get_text("dict")["blocks"]
   # 返回的 bbox 为未旋转坐标 → 用 page.rotation_matrix 变换到显示坐标
   display_bboxes = [transform_bbox(b, page.rotation_matrix) for b in text_blocks]

3. 相交判定（含容差 0.5pt，避免像素级擦边误报）：
   overlaps = [rect_intersect(num_rect, db) for db in display_bboxes if is_text_block(db)]

4. 若任一相交 → 生成 OverlapWarning（提示语 7.3：仅提示，不阻止输出）
```

**限制说明**：按提示语约定，重叠检测只针对**文本块**（`get_text("dict")` 提取的文本）。图片、矢量图形不参与判定；若页码与图片重叠，本阶段无法自动检出（提示语未要求，列为已知限制，见 D9）。

## 5. PDF 操作策略

### 5.1 pikepdf 与 PyMuPDF 的职责分工与协作流程

**职责分工（严格不混用）**：

| 操作 | 承担库 | 说明 |
|------|--------|------|
| 复制页面 | pikepdf | `Pdf.new()` 后 `dst.pages.extend(src.pages)` |
| 插入空白页 | pikepdf | `pdf.add_blank_page(page_size=(w_pt, h_pt))` |
| 旋转页面 | pikepdf | `page.rotate(angle)`（angle 取 90/270，见算法 3）或 `page.rotate(angle, relative=True)` |
| 缩略图/书视图渲染 | PyMuPDF | `page.get_pixmap()` |
| 文本块提取（重叠检测） | PyMuPDF | `page.get_text("dict")` |
| 页码文字绘制 | PyMuPDF | `page.insert_text()`（内容流文字，非图片） |
| 字体嵌入 | PyMuPDF | `page.insert_font(fontname="F0", fontfile=...)` |

**协作流程（先 pikepdf 处理结构 → 再 PyMuPDF 处理内容）**：

```
① 加载模块：pikepdf.Pdf.open(原文件, password=...)
             → 同时用 PyMuPDF(fitz) 打开同一文件做“只读”预览渲染（缩略图/书视图）

② 算法引擎：产出 ProcessPlan（物理顺序 / 页码数字 / 旋转角 / 页码坐标）

③ 输出模块-结构阶段（pikepdf）：
   dst = pikepdf.Pdf.new()
   dst.pages.extend(src.pages)              # 复制全部原页（不修改原文件）
   按 ProcessPlan 顺序重组 dst.pages：
      - 在目标位置插入 add_blank_page(page_size=...) 空白页（原页一律保留，不替换）
      - 对需旋转页：page.rotate(page.planned_rotation)   # 90 或 270（问题 3 修改：按检测/覆盖后的最终旋转角）
   bytes_pdf = dst.save() → 内存字节         # 中间产物（结构已就绪、尚未加页码）

④ 输出模块-内容阶段（PyMuPDF）：
   out = fitz.open(stream=bytes_pdf, filetype="pdf")
   for page in out:
       if 该物理页有页码:
           # 用算法4的坐标（未旋转坐标）绘制
           page.insert_text(point, number_text,
                            fontname="F0", fontsize=…, color=…)
       # 同时/随即可做重叠检测（算法5）
   out.save(输出路径)

⑤ 校验：输出后再次打开确认页数一致、可正常渲染；返回输出路径
```

> 关键保证：①中 pikepdf 与 fitz 打开的均为**原文件只读句柄**；所有写操作只发生在 `dst` / `out` 副本。原文件自始至终不被写入。

### 5.2 页面操作细节（pikepdf）

- **复制页**：`dst.pages.extend(src.pages)` 会做必要的深拷贝/共享，页面内容（文字、图片、标注、原有页码）原样保留，不做任何缩放/移动/删除。
- **插入空白页**：`dst.add_blank_page(page_size=(w_pt, h_pt))`；尺寸由 `BlankPageSource` 决定（来源页 MediaBox 的显示尺寸换算为 pt，1pt = 1/72 inch）。
- **旋转页**：按最终旋转角 `page.rotate(90|270)`（相对旋转时 `page.rotate(angle, relative=True)` 叠加源页自带 `/Rotate`）。**注意**：pikepdf `page.rotate(90)` 语义为设置 `/Rotate=90`，其实际显示效果（顺时针/逆时针）与 PDF 规范解释相关，需在 Stage 2 用方向标记样本验证（见《Stage1 审查报告》"二"）；叠加后用 `page.rotation` 校验最终角度 ∈ {0,90,180,270}（D7）。
- **空白页占位与页码**：空白页若"有页码"（封面背面/推动正面/补齐末页），页码由 PyMuPDF 在内容阶段绘制，页面本身无任何其他内容。

### 5.3 PyMuPDF 坐标系统要点（决定页码绘制正确性）

- **PyMuPDF 所有输入/输出坐标都基于"未旋转坐标系"**（自 v1.17.0 起）：`insert_text` 的绘制点、`get_text("dict")` 返回的 bbox，均指未旋转坐标；`Page.rect`/`Page.bound` 才反映旋转后的显示尺寸。
- 因此对带 `/Rotate` 的页：
  - 页码绘制：先在**显示坐标系**按旋转后尺寸算出目标角（算法 4 步骤 4），再用 `page.derotation_matrix` 变换为未旋转坐标后传给 `insert_text`。
  - 重叠检测：把 `get_text("dict")` 的文本 bbox 用 `page.rotation_matrix` 变换到显示坐标，再与页码矩形求交（算法 5 步骤 2）。
- 若实现阶段发现 `/Rotate` 与坐标换算在目标 PDF 阅读器上存在兼容性问题，可退化为"把旋转烘焙进内容流"（PyMuPDF `page.remove_rotation()` 后页面物理尺寸即旋转后尺寸，所有坐标即为显示坐标，无需换算）——此路径在 Stage 2 作为备选实现并做回归对比。

### 5.4 字体嵌入策略（Times New Roman）

- **目标**：页码以内容流文字绘制（禁止图片化），字体呈现跨阅读器/打印机一致。
- **推荐方案（嵌入 TTF）**：
  1. 定位 Windows 自带 `C:\Windows\Fonts\times.ttf`（应用发布时随 EXE 打包一份，避免目标机缺失）。
  2. PyMuPDF `page.insert_font(fontname="F0", fontfile=times_ttf_path)` 注册嵌入字体。**注意**：`fontname` 必须用非保留名（如 `F0`），因为 PyMuPDF 对内置 Base-14 名（如 `tiro`/Times-Roman）会**忽略 fontfile 参数**（官方文档明确）。
  3. 绘制：`page.insert_text(point, number_text, fontname="F0", fontsize=fontsize_pt, color=color)`。
  4. 文字宽度：用 `fitz.Font(fontbuffer=...)`（同一 TTF）的 `text_length(text, fontsize)` 计算，保证右下角对齐精确。
- **备选方案（Base-14）**：使用内置 `tiro`（Times-Roman），不嵌入字体、文件更小，但渲染依赖阅读器字体替换，存在跨端差异。默认不采用。
- 仅页码使用 Times New Roman；不影响原页面已有字体。

## 6. 加密 / 损坏 PDF 处理策略

### 6.1 检测与处理流程

```
打开文件：
  ① 先尝试无密码打开：pikepdf.Pdf.open(path)        # 或 Pdf.open(path, password="")
     成功 → 继续（同时可用 pdf.is_encrypted 确认是否带加密但可无密打开）
     抛 pikepdf.PasswordError → 判定为加密 → 进入 ②
     抛 pikepdf.PdfError / OSError / 其他解析异常 → 判定为损坏 → 弹窗“PDF 文件已损坏，无法打开” → 退出

  ② 加密处理（UI 弹窗输入密码）：
     try:
         pdf = pikepdf.Pdf.open(path, password=用户输入)
     except pikepdf.PasswordError:
         再次弹窗“密码错误”，可重试或退出
     用户取消 → 退出

  ③ 页数检查：len(pdf.pages) == 0 → 弹窗“PDF 文档无页面” → 退出

  ④ 渲染可用性校验（防御）：用 fitz.open(stream=…) 打开同一文件，确认首页可渲染；
     若 fitz 也失败则按损坏处理（与 ① 弹窗一致）
```

### 6.2 关键 API 与异常类型

| 能力 | API | 说明 |
|------|-----|------|
| 检测是否加密 | `pdf.is_encrypted` | 打开成功后读该属性确认 |
| 密码打开 | `pikepdf.Pdf.open(path, password=...)` | 支持用户/所有者密码 |
| 密码错误 | 捕获 `pikepdf.PasswordError` | 重试或退出 |
| 损坏检测 | 捕获 `pikepdf.PdfError` 及其子类（`PasswordError` 为子类，需先于一般 `PdfError` 判定）、`OSError` | 提示损坏并退出 |
| 空文档 | `len(pdf.pages)` | ==0 即空文档 |

> 提示语要求"损坏 PDF 提示损坏并退出；加密 PDF 弹窗输密码，解密失败则退出"。以上流程即该要求的实现路径。加密 PDF 解密成功后，后续所有操作与普通 PDF 一致（输出文件为未加密新文件）。
