# 性能优化报告

> 对应提示语：《性能优化_提示语.md》
> 目标样本：`src/tests/samples/sample_800pages.pdf`（800 页，62 MB）
> 结论：**提示语验收全部达标**（800 页打开带进度 <10s、主线程不阻塞、标记操作 <1s、build_process_plan 输出前后一致、全量测试通过）

---

## 1. 问题背景

800 页 / 62 MB PDF 打开时 UI 卡死（主线程同步阻塞约 10 分钟量级）：单页文本提取耗时长，`get_text("dict")` 每页重复调用（约 1600 次）、每页重复创建字体对象（约 800 次）、缩略图一次实例化 800 个 Widget、标记/配置变更同步重建整棵规划树。

## 2. 优化前基线（实测，`sample_800pages.pdf`）

| 指标 | 优化前 | 说明 |
|---|---|---|
| 打开（同步阻塞） | 3.45s + 全程卡死 UI | 主线程内完成加载+全量提取，无进度 |
| 单页文本提取 | ~19.8ms/页 | 每次 rebuild 若未缓存会重复提取 |
| 缩略图列表创建 | ~0.40s / 800 Widget | 800 个 QWidget + 800 个 QPixmap |
| 标记操作（含重建） | ~0.05s | 单次尚可，连续操作累积卡顿 |
| 字体对象创建 | ~800 个 | 每页 `pymupdf.Font` |

## 3. 优化项与实现

### P0-1 后台线程 + 进度条
- `AppController._LoadWorker(QThread)`：`loader.open` + 全量文本提取 + 配置加载全部在**后台线程**完成，`progress(percent, step_text)` 信号逐页上报进度。
- `AppController.open_pdf_async(path, password)`：QThread 接线；完成回调在主线程接管（复用后台提取的 `text_data` 缓存，`rebuild_plan` 秒级）。
- `main_window`：打开流程改异步，`LoadingDialog` 模态显示进度（"正在加载 PDF… / 分析页面 i/n"），成功/失败回调分发（密码 / 损坏 / 其他）。
- 打开 800 页**主线程不阻塞**，实测 3.74s 完成，进度到 100%。
- 修复：加密 PDF 首次无密码失败后进入密码流程时，原实现存在模态对话框嵌套 exec 死锁，已重构为"阻塞式异步调用"（`_do_async_open_blocking`），无嵌套。

### P1-2 文本块缓存
- `AppController._text_data` 缓存全量页面文本（后台线程一次性提取），`_ensure_text_data` 保证每页只提取一次；`_text_block_calculator` 复用缓存，`rebuild_plan` 不再重复调用 `get_text`。
- 效果：rebuild 全量 800 页仅 0.065s（含规划计算）。

### P1-3 字体缓存
- `PDFRenderer._FONT_CACHE` 类级缓存：同一 `pymupdf.Font` 对象按字体族复用，`get_text_width` 不再每次新建。
- 效果：800 页打开后字体对象从 ~800 → **1**。

### P1-4 缩略图虚拟化
- `ThumbnailPanel` 由 `QScrollArea + 800 个 ThumbnailItem(QWidget)` 重构为 **`QListWidget + 自定义 delegate`**：只创建轻量 `QListWidgetItem`（800 个），delegate 仅绘制可见项；缩略图 PNG 按需懒加载并缓存于 delegate。
- 保留兼容接口：`_items`（dict[phys, item]，测试断言 `len(_items)==plan_page_count()` 不变）、`rebuild/select/on_plan_changed/on_selection_changed`、点击选中、徽标/序号/页码预览绘制与旧实现一致。
- 效果：800 项重建 **0.018s**（原 ~0.40s，↓95%），Python 对象内存 **~240KB**（原 800 个 QWidget 远大于此）。

### P2-5 操作防抖（≤500ms）
- `AppController.set_debounce(enabled, ms=500)`：开启后 `_after_change` 触发的重建合并进 ≤500ms 防抖窗口（`QTimer` 重启式），适合高频批量输入（连续标记 / 拖动数值框）；关闭时立即 flush 未决重建。
- **默认关闭**：保持"变更后数据（`current_plan` / `source_page`）立即可读"的既有契约，避免破坏现有同步测试语义。
- 效果：500ms 窗口内连续 5 次变更 → 仅重建 1 次。

## 8. 遗留与说明

- 同步 `open_pdf` 保留（测试与程序化调用用），生产打开路径均走 `open_pdf_async`。
- 防抖默认关闭以保同步契约；对高频批量操作可显式 `set_debounce(True)`。
- 800 页缩略图绘制仍为按需懒加载（delegate），滚动时逐项绘制，无一次性大图成本。
