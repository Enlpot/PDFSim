# PDFSim 测试矩阵（Stage 1）

> **项目**：PDFSim —— Windows 桌面单文件软件
> **阶段**：Stage 1 —— 测试矩阵设计
> **文档状态**：待指导者审查
> **版本**：v1.0（2026-08-26）

本文档对应《Stage1_提示语.md》第十一章"交付物 3"，覆盖 15 个测试场景 + 旋转可读性专项验证 + 物理顺序专项验证，并补充跨场景通用验证点（禁止事项检查）。

---

## 0. 测试总则

### 0.1 测试环境

- Windows 10/11 x64；Python 3.11+；PySide6、pikepdf、PyMuPDF（与打包 EXE 同版本）。
- 验证分两层：
  - **单元/算法层**：直接调用算法引擎与输出模块（构造 `ProcessPlan` 断言中间结果）。
  - **集成/UI 层**：通过 EXE 界面操作（打开→标记→输出），人工核验渲染结果与提示行为。
- 所有测试样本均保留原始 PDF 副本，测试后校验**原文件字节级未变**（见第 4 节通用检查）。

### 0.2 样本制作

- 用 PyMuPDF 生成可重复的构造样本（A4/A3 纵向/横向、含书签、含页码、加密、损坏等）。
- **旋转可读性样本必须带方向标记**（四角"顶/底/左/右"角标 + 中心箭头），见第 2 节。
- 加密样本用 pikepdf `Encryption(user=...)` 生成；损坏样本截断/篡改合法 PDF 二进制。
- 性能样本（T09）：程序生成 200 页 PDF。

### 0.3 判定口径

每个场景给出：输入特征 → 预期行为 → 验证重点 → 通过标准。所有"预期行为"以《技术方案.md》第 7 章 D1–D9 **经 Stage 1 审查确认后的结论**为准（D1 旋转方向按文字方向检测、D5 空白页尺寸分场景，均已按《Stage1 审查报告》修订）。

## 2. 旋转可读性专项验证（必做）

**背景**：旋转方向正确性依赖物理判定（D1/D2），不能用"看起来对"代替，必须用方向标记样本实证。

### 2.1 方向标记样本规范

每个需要旋转的样本页（A3 纵向、A4 横向、A3 横向）在**四角**绘制方向角标与**中心**箭头：

- 四角角标：页面上缘中央标注 `顶`、下缘中央标注 `底`、左缘中央标注 `左`、右缘中央标注 `右`（统一字号，浅灰，避免与正文混淆）。
- 中心箭头：水平箭头 → 表示正文正常阅读方向（左→右）。

### 2.2 验证步骤

1. 输入样本 → 输出（含旋转决策）。
2. 用 PyMuPDF 把输出页渲染为 PNG（`get_pixmap()`，会应用 /Rotate，得到显示画面）。
3. 人工/程序判定：把渲染图**逆时针旋转 90°**（模拟"读者站在书右侧逆时针转书 90°"），检查：
   - 中心箭头是否水平朝右（→）；
   - "顶"角标是否在上方、"底"在下方；
   - 正文文字是否正立可读（无颠倒/侧躺）。
4. 记录每个 A3/A4 横向样本的通过/失败。

### 2.3 通过标准

- A3 纵向页：输出 420×297 横向，内容逆时针转 90° 后正立可读（D1：旋转方向由文字方向检测决定，见技术方案 3.3.2/3.3.3）。
- A3 横向页：输出 420×297 横向，内容在展开跨页直接正立可读（不旋转，D2）。
- A4 横向页：输出 210×297 纵向，内容逆时针转 90° 后正立可读。
- A4 纵向页：不旋转，直接正立可读（对照组）。

> 若实测方向与自动检测结果不一致，即判定文字方向检测逻辑或 pikepdf `page.rotate()` 方向假设有误（见《Stage1 审查报告》"二"），测试记录为失败并上报指导者修订。

## 3. 物理顺序专项验证（必做）

**背景**：插入空白页后，后续页的正背面、左右位置、页码位置都必须按**新物理顺序**重新计算（提示语 3.4）。此专项在各插入场景（T06/T11/T12/T13 等）统一执行。

### 3.1 验证方法

对每个含插入空白页的样本，构造期望的"最终物理顺序表"（人工/程序先算好），然后断言：

1. **正背面**：物理序号奇数=正面、偶数=背面（空白页也参与）。
2. **左右位置**：展开视图下偶数在左、奇数在右（第 1 页合起）。
3. **页码位置**：物理奇数→右下、物理偶数→左下（A3 固定右下）。
4. **页码数字**：按算法 2 逐页推算（含"不加页码"跳过序号、背面空白不计）。
5. **级联正确性**：插入一张空白后，其后每一页的上述 4 项都基于新序号成立。

### 3.2 通过标准

- 期望物理顺序表与实际输出逐项一致；
- 至少覆盖一次"插入点在目标页之前导致后续页奇偶翻转"的级联场景（T12/T13 天然覆盖）；
- 原文件内容未被改动（第 4 节通用检查）。

## 4. 跨场景通用检查（每个场景必跑）

| 检查项 | 方法 | 通过标准 |
|--------|------|----------|
| 原文件不可修改 | 处理前后对原文件做 SHA-256 | 哈希一致 |
| 禁止 PDF→图片→PDF | 检查输出内容流存在文字绘制操作、无整页位图重封装（抽样解析 Content Stream） | 无整页图片化回封 |
| 页码为文字非图片 | 输出页文本提取 `get_text()` 能取到页码数字；字体为嵌入 Times New Roman（`get_fonts()` 校验） | 文本可取、字体正确 |
| 禁止覆盖输出 | T15 流程 | 已存在时跳过 |
| 禁止删除/隐藏原页 | 输出页数与 ProcessPlan 物理页数一致；原页内容（文字/图片）抽样比对渲染 | 页数一致、内容保留 |
| 空白页特征 | 依 `BlankPageSource` 校验尺寸/有无页码/是否占序号 | 与 6.2 表一致 |
